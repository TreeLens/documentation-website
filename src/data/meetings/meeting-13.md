## 2. 💬 Discussion and Decisions
### *Topic 1:* VM
- In the next sprint, our focus should be on getting the project onto the VM, with everything running via a runner that will be configured on it.

### *Topic 2:* Municipal Report
- Following the implemented corrections, the points discussed were as follows:
    - The flowchart is too technical. The report will be read by people outside of our field of work, so using the names of specific technologies and processes may cause more confusion than it helps with understanding.
    - Instead, a sequence diagram should be developed that highlights the system's actors and their interaction with the system, rather than what happens inside it.
    - The schedule section of the report can be a bit confusing for those not involved in the project's development. Therefore, to improve comprehension, it was agreed to develop a Gantt chart divided only by epics, not by user stories as initially planned, since that created a large loop. Thus, the larger size of the epics makes the diagram more perceptible and they are accompanied by a subsection of the report that details each one in more detail.

### *Topic 3:* CheckPoint 
- For the checkpoint taking place next Tuesday, it has been decided that the entire project must be placed on the VM, and that only elements from within the VM should be shown.
- We should integrate the API URL into the mobile .env file so that everything can be displayed without a cable connection.
- Focus on demonstrating a complete submission flow, and to do this, the backoffice needs to be more developed.
